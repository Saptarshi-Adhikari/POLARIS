# Simulation Logic

**VERY IMPORTANT:** This describes the JS simulation running in the browser.

## World Representation
- **Grid:** The ocean is discretized into a grid (e.g., 20x20 pixel cells) inside `vectorField.js`.
- **Coordinate System:** Arbitrary Canvas Pixels (X, Y). `(0,0)` is top-left. There is no real-world projection (like Web Mercator).

## Environment Generation
- **Vectors:** Each cell in the `VectorField` has an angle and magnitude.
- **Ocean Currents:** Driven by the `currentSpeed` and `currentDirection` variables.
- **Weather (Wind):** Driven by `windSpeed` and `windDirection` variables.
- **Tides:** A simple sine wave function applied over time (`Math.sin(time / tidalPeriod)`).

## Hazard (Iceberg) Generation
- Default icebergs are instantiated in `main.js` as hardcoded `Iceberg` objects with fixed initial X,Y coordinates, mass, and radius.
- User-added icebergs spawn at the mouse click coordinate.

## Simulation Tick & Update Loop
1. `requestAnimationFrame` calls `loop(timestamp)` in `main.js`.
2. Delta time (`dt`) is calculated.
3. `dt` is multiplied by the UI `timeWarp` factor (1x, 10x, 100x).
4. `vectorField.updateGrid()` recalculates the vectors based on time and sliders.
5. `iceberg.update()` applies vector forces to the iceberg's current position to calculate a new position (Euler integration).
6. `ship.update()` moves the ship along its route waypoints.
7. `aiNavigator.evaluate()` checks if the new iceberg positions intersect the ship's route.
8. `canvasRenderer.render()` draws the new state.

## Variables

| Name | Type | Meaning | Generated By | Consumed By |
| :--- | :--- | :--- | :--- | :--- |
| `currentSpeed` | Float | Speed of ocean current | UI Slider / Preset | `vectorField.js` |
| `windSpeed` | Float | Speed of wind | UI Slider / Preset | `vectorField.js` |
| `timeWarp` | Integer | Simulation multiplier | UI Buttons | `main.js` loop |
| `mass` | Float | Mass of Iceberg | Hardcoded / UI | `iceberg.js` (affects inertia) |

## Scientific Accuracy vs Visual Approximations
**This is entirely a Visual Approximation.**
- It does not use Navier-Stokes equations.
- It does not use real-world drag coefficients.
- It is deterministic based on simple trigonometry and addition (`x += velocity * dt`).
