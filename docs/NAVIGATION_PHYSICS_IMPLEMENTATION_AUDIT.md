# Navigation Physics Implementation Audit

This document serves as the forensic review of the CURRENT repository state (prior to the Phase 2 upgrade).

## 1. Current Simulation Architecture
The system is built on a simple Javascript RequestAnimationFrame loop managed by `main.js`. It runs at ~60 FPS. `VectorField` handles global environment (current, wind), `Ship` handles vessel state, and `AINavigator` computes paths. `CanvasRenderer` paints the state, and `UIController` binds HTML elements to object properties.

## 2. Current Ship Movement Logic
The `Ship` class interpolates velocity directly. While it includes concepts of `vx` and `vy` adding thrust and environmental vectors (Current + Wind), it updates position directly via `x += vx * dt`. Steering relies on `updateAutopilotSteering` which computes an angle difference and sets `rudder`, but does not use a true Newtonian acceleration/force-integration model (`F = ma`).

## 3. Current Route Generation Logic
`AINavigator.evaluate()` checks if the current path is blocked by hazards. If yes, it calls `generateOptimalRoute()`, which uses a highly simplified hardcoded spline approach (4 control points) that manually dodges the center of mass of icebergs. It is **not** a true grid-based A* algorithm, despite the presence of `initRiskGrid`.

## 4. Current Route Rendering Logic
`canvasRenderer.drawSafeRoute()` currently draws a static path based on the waypoints generated by the navigator. It iterates over the array and draws line segments. 
**Why it detaches:** The route rendering starts from `waypoints[0]`, which is the position of the ship *at the time the route was generated*. As the ship moves, the route stays physically anchored to the old starting coordinate on the canvas.

## 5. Current Vector/Current Physics
`VectorField` computes a vector `(u, v)` for any `(x, y)` coordinate based on base current, tidal oscillation (sine wave), wind drift factor, and spatial turbulence (Perlin-like harmonic noise). It provides a good base for continuous physics, but lacks integration with sea ice.

## 6. Current Iceberg Movement
Icebergs (`Iceberg.js` - extrapolated from loop calls) update their position using the `VectorField` velocities, applying a generic current response and wind response multiplier. 

## 7. Current Collision/Risk Logic
`AINavigator` computes a `riskGrid` and a maximum `maxShipRisk` score based on proximity to current and projected (future) iceberg positions. It triggers a reroute alert if the score exceeds a threshold (0.45).

## 8. Current Environment Controls
The current environment controls are handled via `UIController`, which manually binds DOM inputs to `simEngine.vectorField` properties (e.g. current speed, storm mode).

## 9. Current Event-Handling Problems (Panel Closing)
**Why the environment panel closes:** The UI likely uses a global `document.addEventListener('click', ...)` or a `blur` event that fails to distinguish between clicks *inside* the environment panel and clicks *outside* it. Clicking a slider or input inside the panel triggers the global close handler because event propagation isn't stopped (`event.stopPropagation()`).

## 10. Real vs. Decorative Variables
**Real (Affects Physics):**
- `currentSpeed`, `currentDirection`, `tidalStrength`, `windSpeed`, `windDirection`, `stormMode` in `vectorField.js`.
- `ship.throttle`, `ship.rudder`, `ship.heading` in `ship.js`.

**Decorative (Currently Disconnected):**
- Any mention of "Sea Ice" (completely absent from simulation logic).
- Path modes (Shortest, Safest, Balanced) do not exist in the hardcoded spline routing.
- The UI slider for "Icebergs" might just change a visual number without actually spawning/despawning iceberg objects dynamically.
